Tools used in this capstone

One dataset, four tools, one story

Each tool plays a distinct role in the pipeline — interviewers frequently probe why a given stage used the tool it did.

How the same dataset moves through all four tools

Excel: work directly on the dataset — clean it and build the first dashboard straight from the spreadsheet.
Tableau & Power BI: don't connect to the Excel file. First load the dataset into SQL, then connect Tableau and Power BI to SQL as the data source, and build the dashboard from there.
QA: run SQL queries directly against the backend database, then match every count, sum and average against what's shown on the Tableau and Power BI dashboards — that reconciliation is what a QA review actually checks.

Data Pipeline

Market feed → database → ETL → warehouse → BI tools

The full path data actually travels: records get written into the trading system's own source database, ETL extracts and reshapes that into the warehouse, and both BI tools connect only to the warehouse — never to each other, never to the source database directly.

Live-flowing reference, not a literal animation of your data — but this is the real path: nothing reaches Tableau, Power BI, or the AI/insights layer except through the warehouse, and nothing reaches the warehouse except through ETL.

Data Model

Multi-fact schema — Trades & Prices are the hubs

All foreign keys are verified with zero orphan records. Two fact clusters share conformed dimensions: fact_daily_prices carries market data on its own, while fact_orders → fact_trades → fact_trades_pnl_kpi carries this desk's own trading activity.
